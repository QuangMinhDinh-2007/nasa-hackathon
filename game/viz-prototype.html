Earth Missions · Proposal

Procedural mission visuals

Prototype renderers for Storm Watch, Wildfire Watch and Flood Watch. Every scene is generated from a mission-code seed through a separate visual random stream (same hash/PRNG family as scenario.js, stream name visual), so the engine's random sequence is never touched. Same seed → same scene; type a seed or reroll to compare. All imagery is simulated, not real satellite data.

Mission 1

Storm Watch — four storm structures

Clouds come from a continuous density field (seeded fractal noise × irregular spiral rainbands), not geometric wedges. Inner cloud deck rotates slowly against the outer field; pause respects the simulation clock in-game.

Mission 2

Wildfire Watch — four environments

One continuous satellite-style landscape under the existing A / B / C regions. Toggle After scan to see how a detected fire is revealed (thermal hotspot, smoke, burn scar). Before detection, nothing hints at hidden fire events.

Mission 3

Flood Watch — four river valleys

A meandering river over a seeded terrain-height field. The flood slider stands in for the simulation timeline: water fills connected low-lying ground near the river. Radar view swaps to grayscale backscatter with dark water, as in Sentinel-1 / HydroSAR imagery.

Integration plan (awaiting approval)

  • Approach: Canvas 2D, no new dependencies. Each mission view gets one cached offscreen texture per seed (regenerated only on seed change or resize), composited each frame with cheap transforms. Animation is a pure function of simulated time, so pausing the game freezes the scene and replays are identical.
  • Seeding: Scenario.mulberry32(Scenario.hash32(version|mission|seed|'visual')) — deterministic, independent of every engine stream.
  • Files: replace stormArt(), fireArt(), valleyArt() in index.html with canvas mounts backed by a new viz.js. Region outlines, hotspot markers, scanbox, labels and all engine logic stay exactly as they are; the canvas sits under the existing overlays (z-order unchanged).
  • Known limitation stated, not hidden: the engines score coverage with simple geometric models (storm phases, region footprints, zone thirds). Cloud/water art is illustrative; the scoring footprint stays the yellow box and region geometry, and the "Illustration · not real imagery" note stays on screen.
  • Hidden information: fire events and flood extent render only from M.detected / delivered-map state the engine already exposes; undetected events leave no visual trace until the debrief reveal.
  • Performance: textures ≤ 512×342, generated once (<30 ms); per-frame work is drawImage + a few gradients. prefers-reduced-motion renders a static frame.

Validation before merge: four seeds → four distinct scenes (shown above); same seed reproduces; storm pauses with the sim; camera box and track overlays stay readable; engine tests untouched (tools/test_engine.js, wildfire/flood checks) still pass since no engine file changes.
