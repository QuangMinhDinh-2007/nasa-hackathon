# Earth Missions — Mission Lab · v5.0 specification

Built 15 Nov 2026 for the NASA Space Apps Challenge "Space Mission Design Game".
This document describes what the game **does today**, where every number comes from, and what is not finished. It replaces nothing in the three mission specs (Storm Watch, Wildfire Watch v3.0, Flood Watch v4.1); it sits on top of them.

## 1. What changed from the previous build, and what did not

**Unchanged (verified by test):** the three missions, the 5-part Spacecraft Builder, the launch, the four connected 6-hour challenges, the persistent mission state, the dashboard, the Final Report, the score weights 35 / 35 / 20 / 10, the four gates per mission, and the outcome order Failure → Success → Partial. In Practice mode all three engines give exactly the same results as before the upgrade:

| Mission | Runs (valid designs × 256 decision sets) | Success / Partial / Failure |
|---|---|---|
| Storm Watch | 7,936 | 6,292 / 1,544 / 100 |
| Wildfire Watch | 5,376 | 740 / 3,484 / 1,152 |
| Flood Watch | 5,888 | 2,215 / 3,177 / 496 |

**Added (all in separate files, loaded on top of the existing game):**

| File | Purpose |
|---|---|
| `scenario.js` | Mission Codes: seeded, reproducible mission conditions |
| `provenance.js` | Registry of every number with class A/B/C/D, source, link, date checked |
| `nasa-data.js` | Real NASA observations supplied by the team, generated by `tools/build_nasa_data.py` |
| `upgrade.js` | Mission journey playback, crew chat with Pip, readiness review, what-if replay, timeline, record, sources panel |

The three engines gained one optional argument (`scn`) and a trace recorder. With no scenario they run the old code path.

## 2. Number classes

Every number shown to a player belongs to one class. The in-game "Data & sources" panel lists them per mission.

| Class | Meaning | Example |
|---|---|---|
| A | Observed NASA data, read from a file the team downloaded | 38.67 mm/h peak rain rate, IMERG, 27 Sep 2022 |
| B | Published specification of a real mission | GOES-R launch mass 5,192 kg |
| C | Derived by a stated formula | Orbital period at 747 km |
| D | Educational game value | Component costs, science points, fault sizes |

Class D values are **not** presented as NASA values anywhere in the game.

### 2.2 Class C formulas

- Orbital period: `T = 2π √(a³ / μ)`, `a = 6378.137 km + altitude`, `μ = 398,600.4418 km³/s²`. Computed live in `provenance.js` (`periodMin`).
- Longest eclipse per orbit (cylindrical shadow, Sun in the orbit plane): `T × 2·asin(R_E / a) / 2π` (`maxEclipseMin`).
- Storm timeliness weights (≤3 h 100%, ≤6 h 75%, ≤12 h 50%, older 25%) are a class D rule **anchored to** the 3-hour and 6-hour NHC cycle. The weights themselves are a game choice.

### 2.3 Class A data bundled in this build

Produced by `tools/build_nasa_data.py`; file hashes and processing steps are in `docs/data-provenance.json`.

| Dataset | What is in the file | Used for |
|---|---|---|
| NASA FIRMS, VIIRS 375 m active fire, Suomi NPP + NOAA-20, Maui, 8–10 Aug 2023 | 539 detections, 13 overpasses | Wildfire report card |
| GPM IMERG Final half-hourly V07B, one granule, 27 Sep 2022 00:00–00:30 UTC, box 90–78°W 18–32°N | 16,800 cells of 0.1° | Storm report card |
| OPERA DSWx-HLS V1, BWTR layer, two mosaics, 2 and 5 July 2025, UTM 14N, 30 m | pixel classes | Flood report card |

Findings computed from these files:

- **FIRMS:** the longest gap between overpasses was 10 h 49 min (00:36 → 11:25 UTC, 9 Aug). Detections in the box went from 11 to 131 across that gap. Median fire radiative power 6.4 MW, maximum 134.8 MW. A detection is a 375 m pixel flagged as fire; it is not a count of fires or a burn perimeter. The West / Central / East split is a longitude band chosen by this project for display.
- **IMERG:** peak 38.67 mm/h at 20.65°N, 83.55°W; mean 1.07 mm/h; 39.9% of cells with rain ≥ 0.1 mm/h; 1.8% with ≥ 10 mm/h.
- **OPERA:** cloud or cloud shadow covered 92.6% (2 July) and 87.5% (5 July) of mapped pixels. Open water in the clear part: 12.69 km² and 9.85 km².

**Rule:** none of these observations changes a score, a target, or an event in any mission. They appear in a card titled "What NASA satellites really saw", tagged REAL NASA OBSERVATIONS, in the Final Report. The mission maps stay labelled as synthetic training scenarios.

**Known limits of the data:**

1. IMERG is one half-hour. It is a snapshot, not a storm history.
2. The two OPERA mosaics cover different areas. Kerrville, Hunt and Ingram are outside the 2 July mosaic and in the no-data part of the 5 July mosaic. No before/after flood map can be made, and the two water areas cannot be compared.
3. The Maui fires caused many deaths. The card says so and the data is not a playable level.

## 3. Mission Codes (seeded scenarios)

**Format:** `STORM-7K3QX`, `FIRE-7K3QX`, `FLOOD-7K3QX`, or `…-PRACTICE`. Five characters from an alphabet without I, O, 0, 1. Input is case-insensitive.

**Modes:** Practice (no surprise events, the calibrated baseline) · Surprise (new random code) · Classroom (type a code the teacher gives).

**Generator:** FNV-1a 32-bit hash of `mission | seed | scenario version | stream name` seeds a mulberry32 generator. Three independent streams: `power`, `ground`, `environment`. The whole event schedule is generated before the mission starts and never reads player decisions. `Math.random` is used only to pick a new Surprise code, never inside an engine.

**Guarantee (tested):** same code + same scenario version + same engine version + same design + same decisions ⇒ identical results, in Node and in the browser.

**Event ranges (class D, labelled in the game as "simulated events, not NASA data"):**

| Mission | Stream | Event | Range | Practice value |
|---|---|---|---|---|
| Storm | power | Solar generation during the hours 12–18 fault | 30 / 35 / 40 / 45% | 35% |
| Storm | ground | Rain at the ground station halves the downlink for 2 h | start hour 1–19 | none |
| Storm | environment | Earth-shadow pass, no solar power for 1 h (50% of codes) | hours 3–10 or 19–22 | none |
| Wildfire | power | Solar generation during the fault | 10 / 15 / 20 / 25% | 15% |
| Wildfire | ground | One contact starts 30 min late | contact 1–4 | none |
| Wildfire | environment | Smoke lowers detection to 85% on one pass (50% of codes) | pass 1–3 | none |
| Flood | power | Solar generation during the fault | 20 / 25 / 30 / 35% | 25% |
| Flood | ground | One contact is 5 min shorter | contact 1–7 | none |

Why these limits: the Storm shadow hour is rounded down from NOAA's 72-minute maximum to fit hourly reporting. Smoke never falls on the final Wildfire pass, because testing showed only 2 of 21 valid designs could still succeed if it did. No event can end a mission by itself.

## 4. Other features in v5.0

| Feature | Behaviour |
|---|---|
| Mission journey | After the player confirms a challenge, the satellite's 6 hours play back from the engine's trace: clock, battery, storage, data delivered, event log. The engine computes first; playback speed (1× / 3× / skip) cannot change a number. The journey stops at each challenge until the player decides. |
| Pip and the crew | Pip (an original bird mascot) guides the player in a chat panel. Dr. Maya (science), Alex (power) and Sam (communications) each give advice before a decision. Their forecasts come from running the real engine ahead on a copy of the mission state with no surprise events, so advice is never invented. Optional voice uses the browser's speech engine. |
| Prediction | Before running a challenge the player predicts whether battery will go up, stay, or go down. The result screen says whether the prediction was right. Not scored. |
| Click the map | On challenges with a footprint choice, clicking the map switches wide ↔ targeted. |
| Mission Readiness Review | Before launch, a four-part check: Launch (mass, budget), Space (power margin, storage), Ground (downlink), User (does the design fit the mission goal). Follows the segment structure taught in the challenge resources. |
| Change one decision | The Final Report replays the mission 8 times, each with exactly one decision flipped, same design and same code, and shows the score and outcome of each. |
| Cause-and-effect timeline | Decisions, simulated events and their consequences in time order. |
| Compare attempts | Last attempt against this attempt, with a note that changing several things at once hides the cause. |
| A real mission like yours | GOES-R, NOAA-20/VIIRS, NISAR facts from section 2.1. |
| Guidance levels | Guided / Standard / Expert change how much the crew explains. They do **not** change physics or scoring. |
