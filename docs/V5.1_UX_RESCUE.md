# Earth Missions v5.1 — UX rescue and direct controls

Built 15 Nov 2026 in response to the team's feedback on v5.0: robotic voice, a text-heavy corner mascot, a flashing screen, and too little real interaction.

## 1. What a player can do now that they could not do before

| Storm Watch challenge | Before (v5.0 and the original) | Now (v5.1) | How it reaches the result |
|---|---|---|---|
| 1 · Aim the camera | pick Wide or Focused | drag and resize a scan box over a forecast track and its cone of uncertainty | the engine computes, hour by hour, how much of the storm is inside the box; box size sets image detail and file size |
| 2 · Sort the data | pick a storage rule | mark each stored image Send first / Keep / Discard | Send first changes the downlink order; Discard deletes the image and frees storage |
| 3 · Plan six hours | pick Normal or Power-save, Frequent or Occasional | set each hour to Full / One image / Eco / Rest, with a battery forecast per hour | the engine runs that hour with that mode |
| 4 · Emergency downlink | pick speed and power mode | reorder the stored images, choose whether new storm images jump the queue; each image shows its arrival time | the engine sends in that order; the critical update can be missed |

Every forecast shown before confirming comes from running the real engine ahead on a copy of the mission. After each challenge one note says what actually happened (for example the real storm path against the forecast).

Wildfire Watch and Flood Watch keep their option screens. They lost the mascot, voice and flicker only.

## 2. Before / after

| Problem reported | Cause found | v5.1 |
|---|---|---|
| Screen flashes after every decision | every re-render replayed the page fade-in; the scan box flashed on each capture; playback rebuilt the whole page | the fade plays only when the screen changes; the flash is removed; playback updates only the dashboard numbers and the log; battery and storage bars move smoothly between hourly values |

## 3. Engine changes (Storm Watch, storm-3.6.0)

- New optional `M.ext` per challenge: `{box}`, `{first, drop}`, `{sched}`, `{order, newFirst}`.
- With no `ext`, results are identical to before: 6,292 / 1,544 / 100 over all valid designs × 256 option sets (tested).
- A full-size box gives exactly the old Wide result (tested). Six Full hours equal Normal + Frequent; six Eco hours equal Power-save + Frequent (tested).
- The old Focused option had a fixed 60% / 30% chance of seeing the storm. That number is now computed from where the box is.
- Score weights 35 / 35 / 20 / 10, the four gates and all thresholds are unchanged.
- New class D values (game model, not NASA figures): storm core radius 0.08 of the map, forecast step, cone growth 0.16, drift −1 … +1 set by the Mission Code (Practice: +0.5), minimum box size 50%.
- The Mission Code now also fixes the storm's drift, through a separate random stream. Existing codes keep the same events as in v5.0.

Effect of the scan box on balance (all valid designs × 128 option sets, Practice drift):

| Box | Success | Partial | Failure | Mean score |
|---|---|---|---|---|
| Whole disk (old Wide) | 3,048 | 872 | 48 | 88.2 |
| Tight, centred on the forecast track | 3,641 | 275 | 52 | 89.9 |
| Tight, left on the storm's starting point | 3,357 | 559 | 52 | 89.5 |
| Covers the whole cone | 3,067 | 857 | 44 | 87.7 |

Honest reading: aiming well helps, but the effect on the final score is small (about 1–2 points on average), because a tight box also makes smaller files. A badly placed box does hurt: in one tested design, science collected in challenge 1 fell from 5.13 to 0.76 points. The team may want a stronger effect; that needs a threshold change and is left for the team to decide.
